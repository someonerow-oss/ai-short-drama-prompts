# 工作流：小说 / 梗概 → 分镜表

> 目标：把一段中文剧情梗概，稳定地转成**结构化分镜表**（可直接喂给出图/出片流程）。

## 一、为什么要用 JSON 而不是让模型自由发挥

自由发挥的分镜文本无法批处理：字段不全、镜号乱跳、时长对不上、风格描述每次不同。
**用固定 schema 让模型填表**，一次生成 20 镜，可直接转 CSV、可校验、可迭代。

## 二、分镜表 JSON Schema

```json
{
  "episode": 1,
  "genre": "都市甜宠",
  "style_prefix": "cinematic film still, photorealistic, anamorphic lens, film grain, shallow depth of field",
  "total_duration": 60,
  "characters": [
    {
      "name": "林晚",
      "desc_block": "25岁女性，鹅蛋脸，丹凤眼，黑色长直发及腰，偏瘦168cm，银色细项链",
      "looks": {
        "LOOK-01": "米白色长风衣，黑色高领针织衫，黑色直筒西裤",
        "LOOK-03": "香槟色真丝晚礼服，盘发，珍珠耳坠"
      }
    }
  ],
  "shots": [
    {
      "shot": "001",
      "seg": 1,
      "dur": 1.5,
      "size": "medium close-up",
      "angle": "eye-level",
      "move": "static",
      "lens": "85mm, shallow depth of field",
      "content": "雨中，林晚手捧便当盒，看着远处车子驶离",
      "line": "",
      "sfx": "雨声，引擎声",
      "look": "LOOK-01",
      "light": "soft overcast daylight, cool 5600K, backlit rain",
      "prompt": "",
      "note": "参考帧 REF-林晚-FRONT.png"
    }
  ]
}
```

`schema` 里 **`prompt` 字段留空**，由本地脚本按公式拼接（保证格式统一，模型不擅长的机械拼装交给代码）。

## 三、转分镜提示词（直接复制使用）

```
你是短剧分镜师。请把下面的剧情梗概转成 JSON 分镜表。

硬性要求：
1. 输出纯 JSON，不要任何解释文字、不要 markdown 代码块标记。
2. 严格遵守给定的 schema 字段名，不得增删字段。
3. 时长分配：60 秒对应 20 镜，按六段式节奏
   （钩子 0-3s / 交代 3-14s / 升级 14-34s / 反转 34-45s / 爽点 45-57s / 悬念 57-60s）
   等比缩放段时长，但保持六段结构完整。
4. 每镜 duration 在 1.0~6.0 秒之间；升级段与爽点段用 1.5~2.5 秒，情绪段用 4~6 秒。
5. 每镜 prompt 字段留空字符串 ""，不要填写。
6. 每镜必须有 look 字段，值来自 characters[].looks 的键名。
7. content 字段只描述"谁、在哪、做什么"，一句话，禁止堆叠两个以上动作。
8. 第 1 镜必须是冲突画面，禁止用交代背景的镜头开场。
9. 最后一镜必须是新悬念，禁止圆满收尾。
10. 场景数量控制在 6 个以内（便于美术风格统一）。

题材：{题材}
风格前缀：{style_prefix}
角色设定：{characters}
剧情梗概：{梗概}
```

## 四、本地拼接 prompt（Python 示例）

```python
def build_prompt(style_prefix, char_desc, look_desc, shot):
    return ", ".join([
        style_prefix,
        f"{char_desc}, wearing {look_desc}",
        f"{shot['size']}, {shot['angle']}, {shot['move']}, {shot['lens']}",
        shot['light'],
        shot['content'],
        shot['emotion'],
    ])
```

拼接顺序固定为：**风格前缀 → 角色描述块（含 LOOK）→ 镜头语言 → 光线 → 场景内容 → 情绪**。
顺序固定有两个好处：① 关键词权重稳定；② 出问题时能快速定位是哪一层写错了。

## 五、质量校验脚本（必做）

生成 JSON 后先跑校验，不通过就别出图。仓库里已经带了可直接用的版本：

```bash
python tools/validate_shots.py examples/都市甜宠-第1集-分镜表.json
# → 镜数: 20  总时长: 60.0s  题材: 都市甜宠
# → 校验通过 ✅
```

它检查：六段结构是否完整、总时长是否偏差过大、镜数下限、单镜时长区间、
`look` 是否引用了已定义的造型、`content` 是否过长（塞了多个动作）、`prompt` 是否被误填、
以及必填字段是否齐全。下面是它的核心规则（可自行扩展）：

```python
def validate(data):
    errs = []
    total = sum(s['dur'] for s in data['shots'])
    if abs(total - data['total_duration']) > 5:
        errs.append(f"总时长偏差过大: {total}s vs {data['total_duration']}s")
    if len(data['shots']) < 15:
        errs.append(f"镜数过少: {len(data['shots'])}")
    segs = {s['seg'] for s in data['shots']}
    if segs != {1, 2, 3, 4, 5, 6}:
        errs.append(f"六段结构不完整，缺段: {set(range(1,7)) - segs}")
    looks = {l for c in data['characters'] for l in c['looks']}
    for s in data['shots']:
        if s['look'] not in looks:
            errs.append(f"镜 {s['shot']} 引用了未定义的 LOOK: {s['look']}")
        if len(s['content']) > 60:
            errs.append(f"镜 {s['shot']} content 过长，可能塞了多个动作")
        if s['prompt']:
            errs.append(f"镜 {s['shot']} prompt 应为空（由脚本拼接）")
    return errs

errs = validate(data)
for e in errs:
    print("ERR", e)
```

## 六、迭代节奏

1. **第一轮**：只让模型出 JSON，不出图。人工过一遍六段节奏和钩子强度。
2. **第二轮**：改梗概，重新生成。**只调梗概，不要手改 JSON 结构**（结构与节奏问题应回到梗概层面解决）。
3. 定稿后：跑校验 → 拼 prompt → 出定妆包（`prompts/03-角色一致性.md`）→ 批量出图。
4. **出图顺序**：先出第 1、4、5 段（钩子/反转/爽点），这三段决定成片能否留住人。其余段最后补。

## 七、常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| 模型只给 8~10 镜 | 没写死镜数下限 | 提示词里明确"18~20 镜，不得少于 18" |
| 六段缺段 | 模型合并了段 | 在校验脚本里强制断言，不通过就重跑 |
| 每镜都写了 prompt | schema 没强调 | 在 prompt 模板中重复"prompt 字段留空" |
| 时长乱给 | 未约束单镜区间 | 明确 1.0~6.0 秒并给出分段建议 |
| 场景太多（10+） | 梗概跨度太大 | 把梗概按集拆分，一集一个主要场景 |
